1Writing a function

A function takes some input (its parameters), does something with it, and sends a result back with return.

function double(n) {
  return n * 2;
}

double(5) runs the function with n set to 5, and gives you back 10. Nothing happens until it's actually called.

Common mistake: writing the logic but forgetting return — the function runs, but silently gives back undefined instead of your answer.

2Booleans and comparison

A boolean is just true or false. Comparison operators produce one:

Keyboards don't have a single ≥ key, so code spells "greater than or equal to" as two ordinary characters, back to back: > immediately followed by =. Read >= as one operator, not a > with something bolted on.

function isAdult(age) {
  return age >= 18;

Common mistake: mixing up > and >=. "Over 18" excludes exactly 18; "18 or over" includes it. Read the brief carefully — it's usually specific on purpose.

3If / else

Run different code depending on a condition. The first condition that matches wins — the rest are skipped.

function describe(n) {
  if (n > 100) {
    return "big";
  } else if (n > 10) {
    return "medium";
  } else {
    return "small";
  }
}

Order matters

Checks run top to bottom. Put the most specific or most extreme condition first — if you check the broadest one first, the narrower ones never get a chance to run.

4What "testing" means here

Each test case calls your function with specific input and compares what it actually returns against what it's expected to return. A test only passes when those match exactly — a function that works for one input but not another still fails overall.

Check yourself

1. A function has correct logic but no return statement. What happens when you call it?

JavaScript doesn't guess what you meant to return — no return statement means undefined comes back, no error, no warning.

2. Which correctly means "16 or older"?

"16 or older" includes exactly 16, so you need the "or equal to" version — >= not just >.

3. In an if/else chain, why does order matter?

Once one condition matches, its branch runs and the rest are skipped entirely — that's why the most specific case usually needs to come first.
