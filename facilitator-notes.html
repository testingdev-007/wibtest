The dashboard's "I'm interested in..." picker

A small feature on index.html — five toggleable chips (Coding, Web Design, AI Prompting, Data & Dashboards, Debugging) that highlight matching module cards and dim the rest when clicked, multi-select. Several modules genuinely belong to more than one category: Ledger is tagged both Coding and Data (it's the array/query module, and directly connects to the Excel dashboard exercise); Helpdesk is tagged both Coding and Debugging (it's the one module that's purely about fixing rather than writing); the Excel/Outlook exercise is tagged both AI Prompting and Data. This is genuinely useful mainly once there are enough modules that browsing all of them at once feels like a lot — point newcomers at it if they seem unsure where to start.

The 25-minute slot

Five stations, roughly 5 minutes each, with a short buffer for moving between them. The Construct taster has a visible on-screen countdown set to 6 minutes — the other four don't enforce a timer, so you'll need to call time yourself.

Construct ~5m
Vault ~5m
Ledger ~5m
Front ~5m
Helpdesk ~5m

Nobody needs to finish every task in every activity — the point is a real taste of each, not full completion. If someone's clearly engaged and close to finishing when time's up, let them carry on; don't cut mid-flow over a minute or two. Construct and Vault now have 5 tasks each rather than 3 — genuinely finishing either one in 5 minutes is a stretch goal, not an expectation.

Hello, Computer

What it is: hello-world.html, first on the dashboard, mandatory before everything else. A 3-minute warm-up that explains what a "console" actually is — plain-English, no assumed knowledge — then walks through a real console.log("Hello, World!") exercise, then a second step swapping in your own name. Ends with a short recap plus a "why this matters for real jobs" note.

This exists specifically because "people don't know what a console is" was repeated, direct feedback. Every other coding activity assumes this has already been done — several of them (Construct's terminal, in particular) explicitly call back to it ("This works like the console from Hello, Computer..."). If someone skips straight to another activity without doing this first, that callback language may not land, so it's worth actually enforcing "start here" rather than treating it as optional, even though nothing technically blocks skipping it.

Validation is deliberately forgiving. Smart quotes from phone/tablet autocorrect are normalised so they don't unfairly fail someone typing on a touchscreen. Empty submissions get a specific "the box is empty" nudge rather than a generic error. Typos get a constructive retry message, not just "wrong."

The Construct

What it is: navigating a hidden rover across a grid by writing real JavaScript — moveForward(), turnLeft(), turnRight() — building from a single command up to a loop, and explicitly showing that a loop and manual repeated calls are equally valid solutions. Covers functions, sequencing, parameters, and loops.

The goal genuinely wasn't obvious as a goal — feedback confirmed this, and checking the actual rendering confirmed why. The target cell was only a soft colour difference plus an abstract pulsing ring, with no icon and no plain-language statement of the objective anywhere on screen — brief text called it "the exit node," a term that never visually connected to that pulsing circle. Fixed in both the taster and full build: the target cell now shows an actual 🏁 flag icon, a plain "🏁 Your goal: get the rover to the flag" banner sits directly above the grid, and every brief, hint, and terminal log message was updated to consistently say "flag" instead of "exit"/"exit node," so the words and the visual reinforce each other. Confirmed the flag renders on the correct cell across every level in both files, including the newest one (The Rectangle), and confirmed the win condition and log messages still work correctly end to end.

Important — the take-home is not "the same plus one task": levels 1–3 (Wake Up, The Path, The Turn) are byte-identical between the taster and the take-home. Levels 4 and 5 genuinely diverge — the taster has The Relay and The Repeat; the take-home has Agents and The Loop instead. A participant doing both will redo 60% of the content before hitting anything new, which is exactly why it can feel like barely an extension even though two levels do differ, not one. A brand new 6th level, The Rectangle, was added specifically to address this — see the take-home table below.

The Repeat is worth knowing about specifically: the path staircases diagonally rather than running in a straight line — deliberately, after feedback that a straight run didn't feel meaningfully harder than earlier tasks, just longer. The repeating unit is four commands (move, turn, move, turn back), not one, so the manual solution is genuinely long (16 lines) while the loop version stays at 4 — a much more dramatic and honest demonstration of why loops matter. The checking logic still only ever looks at where the rover ends up, never at what code got it there, so both the 16-line manual solution and the 4-line loop genuinely pass.

The Ledger

What it is: writing functions that loop through a real, visible list of transactions to answer questions — totals, filters, counts. Each function also gets tested against a second, hidden dataset, so hardcoding the visible numbers doesn't pass. Covers variables, arrays, objects, and loops.

If this was confusing before, it's had a real fix: the panel showing the data now explicitly spells out that row 1 (groceries, £120) is transactions[0].category and transactions[0].amount in code — that bridge was missing before and was very likely the actual cause of confusion, not the difficulty of the task itself. There was also a genuine layout bug where, on any narrow screen, the code editor rendered above the data table — fixed so the data always shows first.

sumByCategory
function sumByCategory(transactions, category) {
  let total = 0;
  for (let i = 0; i < transactions.length; i++) {
    if (transactions[i].category === category) {
      total += transactions[i].amount;
    }
  }
  return total;

countHighValue
function countHighValue(transactions, threshold) {
  let count = 0;
  for (let i = 0; i < transactions.length; i++) {
    if (transactions[i].amount > threshold) {
      count++;
    }
  }
  return count;
}
largestTransaction (extension)
function largestTransaction(transactions) {
  let biggest = 0;
  for (let i = 0; i < transactions.length; i++) {
    if (transactions[i].amount > biggest) {
      biggest = transactions[i].amount;
    }
  }
  return biggest;
}
averageTransaction (extension)
function averageTransaction(transactions) {
  let total = 0;
  for (let i = 0; i < transactions.length; i++) {
    total += transactions[i].amount;
  }
  return Math.round(total / transactions.length);
}
sumByCategories (extension)
function sumByCategories(transactions, categories) {
  let total = 0;
  for (let i = 0; i < transactions.length; i++) {
    if (categories.includes(transactions[i].category)) {
      total += transactions[i].amount;
    }
  }
  return total;
}

The Front

What it is: writing real CSS against a live preview to hit stated visual goals — checked by reading actual computed styles, not exact pixel matching. Covers selectors, the box model, typography, and flexbox.

Two real changes worth knowing about: there's now a colour picker next to the editor — click a swatch and it shows the hex code to copy, and the brief also says a plain colour name like navy works exactly as well as a hex code. Separately, the worked examples used to use values that would pass the actual checks if copied verbatim with just the selector renamed — that's fixed. The worked examples still show the right properties, but with deliberately small or slightly wrong values (e.g. justify-content: center instead of space-between), so a blind copy-paste no longer passes — genuine adaptation is required.

The Helpdesk

What it is: a completely different mechanic from the other four — a live banking app is broken in five ways, and the participant plays with it, describes what's wrong to a support chat in their own words, and the chat summarises the problem, applies the fix directly to the code, and shows a diff of exactly what changed. No manual find-and-edit required. Two more "issues" are actually just polish suggestions, not bugs, to reward people who suggest improvements as well as spot faults.

There's no visible bug list. The old version showed a checklist naming all 5 known issues, which made the activity pointless — you could just read the list. Now there's only a progress bar showing how many have been found, never what they are. Discovery has to come from actually playing with the app.

The 5 real bugs — now randomised, two variants each

Each session, one of two genuinely different mistakes is picked at random per bug — not just different wording, different actual code. A participant who compares notes with someone else may see a different broken line for the same symptom. Both variants below are real; recognise either.

A real, disruptive bug was found and fixed in the transfer validation fix specifically: the fix originally rejected bad amounts with a real, blocking browser alert('Enter a valid amount'). Helpdesk's own "Check My Fixes" verification actually simulates entering a negative and an oversized transfer to test that validation works — so once that fix was applied, running the verification would genuinely pop up that alert, interrupting the person mid-check with no warning. The alert() has been removed entirely from both variants of the validation fix; it now rejects silently, and the underlying logic is unchanged and still correctly blocks bad transfers.

Help & Hints — what works and what doesn't

This section has been rebuilt twice since it was first written — worth reading in full even if you've seen an earlier version. Construct, Vault, Ledger, and Front now share one menu-driven system: 💡 Hint, ❓ Help, and ✏️ Write it yourself, all inside the same chat panel.

How it works now

💡 Hint posts the same tiered, gated hint sequence as before — clicking repeatedly (with a genuine Run between tiers) walks through hint 1, 2, 3.
❓ Help opens two categories, Syntax (how do I write this) and Troubleshooting (why isn't this working), each listing that module's real reference topics — clicking one shows the answer directly, no typing needed.
✏️ Write it yourself is a genuine free-text box — this was removed at one point in favour of pure menus, then restored after feedback that the pure-menu version answered far too little. Typing "I'm stuck" here still drives the exact same hint progression as the button.
What it still can't do: understand a genuinely novel phrasing that doesn't overlap with any known keyword. That gets an honest fallback pointing back at the Help menu — not silence, but not magic either.

A real, measured comprehension bug — found and fixed

Free text was matching far less than it should have, and there was a provable reason: a stress test of 20 realistic phrasings failed 30% of the time before investigation. Three separate causes, all fixed: (1) the normaliser was silently deleting >=, <, and other symbols before matching — asking "what does >= mean" became "what does mean", losing the entire question; (2) the word "if" was both hard-coded into the stopword list and filtered out again by a length rule, so no if/else question could ever match; (3) plurals didn't match singulars at all — "explain booleans" failed against a keyword list that only had "boolean". All three fixed (symbols are translated to words first, "if" is no longer blocked, and a lightweight stemmer now treats "booleans"/"boolean" as the same word) and re-verified with the same battery plus a second, broader one — 100% on both afterward, with off-topic nonsense still correctly falling back rather than false-matching.

Vault and Ledger's hardest extension challenges — the actual cause, not a vague "make it easier"

Both modules quietly introduced a brand new syntax element for the first time in an extension challenge, cold, with no warmup: Vault's applyLoyaltyDiscount suddenly needed a ternary; flagSuspiciousActivity suddenly needed &&; Ledger's sumByCategories suddenly needed .includes(). None of these had appeared anywhere in the taster. For Vault, the tests never actually required the new syntax at all — they only check output values — so the hints now explicitly say "you already know how to do this with if/else, that works fine" before presenting the shortcut as optional, not required. Both approaches were verified through the real test-running code, not just reasoned about. Ledger's .includes() had no such familiar fallback, so instead the brief now introduces it in total isolation, with a standalone true/false example, before the real task ever appears.
Follow-up after continued difficulty reports on these same challenges: all 6 of the hardest extension challenges (Vault's last 3, Ledger's last 3) now have a 4th hint tier, inserted just before the final full-answer hint — a completely worked example using real plugged-in numbers (e.g. flagSuspiciousActivity walks through amount=6000, country='US' step by step, arriving at true, then re-checks with country='UK' to show why it flips to false). This sits between "here's the concept" and "here's the code," rather than jumping straight from one to the other. All four tiers were confirmed to deliver correctly in sequence through the real hint-gating mechanism, not just read for accuracy.
Second follow-up, same 6 challenges: now at 6 hint tiers total, not 4. A 5th ("fill in the blank," e.g. return isPremium ? amount * ___ : amount;) and a 6th ("a common slip on this one is...", naming a specific realistic mistake like writing & instead of &&) were both added after repeated requests for more. All 6 tiers per challenge confirmed present in the shipped files and delivering correctly in sequence, not just assumed from having built them once before.
"Is the take-home actually different from the taster?" is no longer something to just explain — it's now visible on screen. All 4 take-home files (Vault, Ledger, Construct, Front Extended) show a clear amber "🆕 New — not in the taster version" marker at the exact point new content begins. For Vault/Ledger/Construct that's per-challenge (challenges/levels 4 onward); for Front Extended, which is a single continuous page rather than one-at-a-time challenges, it's a banner near the top naming exactly which sections are new (1, 2, and 4) and which one substantially overlaps the taster (3, the Account Card). Confirmed the badge shows and hides at the correct boundary in each file, and correctly stays hidden during Construct's bonus round, which is a separate mechanic from this taster-vs-take-home comparison.

Helpdesk chat — what works and what doesn't

This is now free-text only — there is no menu at all. An earlier version added a clickable button menu (pick an area, then pick the symptom you'd observed) to make blind clicking less trivial, but feedback was that a 10-year-old still blitzed through it just by clicking. The whole menu was removed entirely, not just hidden — opening the chat shows a text box and nothing else. Describing a problem gets: a one-line summary, the fix applied directly into the code editor, and a red/green diff.

How it behaves

Recognised problems and improvements (7 total, see the answer key above): each has roughly 7-12 different phrasings it recognises, across whichever of the two random variants is actually active that session.
"I'm stuck" is the only way to reach the progress-aware nudge now — there's no dedicated button for it anymore, so the phrase list was deliberately widened ("what am I missing", "what's left", "not sure what else") since this is the sole door into that feature.
Fixes stack correctly: describing a second problem after the first applies its fix on top, without undoing it.
General debugging questions are now answered too, not just bug descriptions: "what is a bug", "what does the diff mean", "what does Check My Fixes do", "what is a function/variable" all get direct answers — added after feedback that this chat should "help like the others" do with general concepts. Checked in this order: stuck-phrase → bug/improvement match → general concept → honest fallback, so a real bug description is never mistaken for a concept question.
What it can't do — genuinely open-ended interpretation: still keyword matching underneath, just with a wide net. It cannot diagnose a problem it wasn't built to recognise.
Manual editing still works alongside chat: participants can type directly into the code window instead of using chat at all — "Check My Fixes" runs the same checks either way.
Badges now exist here too: finding and fixing all 5 real bugs shows a gold badge and an explicit Return Home button, matching every other module — this was missing for a while and has been added.

A separate "I'm stuck" path, for the harder-to-spot bugs

Feedback during testing was specific: for someone with no coding background, finding the last one or two bugs by clicking around is genuinely hard — the transfer-validation and missing-transaction bugs especially don't announce themselves the way a visibly broken button does. Rather than add them to a visible list (which would recreate the exact spoiler problem the redesign removed), there's now a second, separate detection path in the same chat.

How it works: phrases like "I'm stuck", "help", "what should I look for", or "I can't find any more bugs" are checked before the normal fix-matching — if recognised, the chat looks at which of the 5 real bugs haven't been found yet and nudges toward exploring one of them, without naming it. "Try transferring something unusual — a negative amount, or more than the balance actually has. What should happen, and what does?"
It tracks real progress, not a script: the nudge is generated from the same pass/fail state "Check My Fixes" already tracks — it will never point someone back at a bug they've already fixed, and once all 5 are genuinely found it says so plainly instead of repeating itself.
"im stuck" (nothing fixed yet)→ nudges toward the deposit bug specifically
"can't find any more bugs" (3 of 5 fixed)→ nudges toward one of the 2 remaining, never a fixed one
"help" (all 5 fixed)→ "you've actually found everything I know about"

Troubleshooting — user error, not the build

Every one of these has come up in testing and is a person doing something reasonable, not a bug in the files.

"I clicked Run and nothing happened."Check the Error box beneath the buttons — a syntax error (missing bracket, missing semicolon) stops the code from running at all, and the message is usually specific enough to spot the line. If the Error box is empty too, check they actually edited the function body — an empty // TODO with nothing added runs fine and just does nothing.
"My answer looks right but it's still failing."Almost always exact wording/case: "Groceries" won't match "groceries", and a typo'd function name means the test can't find the function at all — the error message will say so directly.
"The page looks completely unstyled / broken, no colours, no layout."These are self-contained single files with no other dependencies except a Google Fonts import — this is almost always a font failing to load over a blocked network. Check internet access on that machine.
"I can't type in the code box."Click directly inside the text area first — cursor focus can land on a button instead, especially on a trackpad. Not a bug, just needs a click.
"I hit Reset and lost my code."Working as intended — Reset wipes back to the starter code for that task, not just the visuals. Worth warning the room about this once up front rather than after someone loses a few minutes of work.
"The test console shows a weird value like NaN or undefined."NaN usually means a maths operation happened on something that wasn't a number (often a typo'd property name). undefined almost always means a missing return.
"Nothing in The Front changes when I edit the CSS."Check the selector actually matches — .account-card needs the dot; without it, it silently targets nothing.
"I copied the worked example exactly and it still failed."Working as intended, not a bug — Front's worked examples deliberately use values too small (or, for Layout, a different value entirely) to pass the real checks. Explain this is on purpose: the pattern is right, the numbers need adjusting.
Construct taster vs. full build — genuinely different levels 4 and 5, not just "full has one extra": both share Wake Up, The Path, and The Turn, but then diverge — the taster's own levels 4–5 are The Relay and The Repeat (documented above), while the full build has Agents and its own version of The Loop instead. The full build's Loop got the identical staircase redesign as the taster's Repeat, for the same reason (a straight line didn't feel meaningfully harder) — just slightly longer (5 diagonal cycles instead of 4), since it's untimed take-home work. Loop's answer is the same shape as Repeat's: a 4-line loop body of move/turn/move/turn-back, repeated, or the fully manual 20-line equivalent — both genuinely pass. The taster is a genuinely different file (mission-control-taster.html) with its own 6-minute timer. Don't hand out the full mission-control.html link during the live event by mistake — its timer now counts up with no deadline, which will look odd if someone's expecting a countdown.
