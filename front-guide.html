1Targeting an element

A class selector starts with a dot and matches anything on the page marked with that class name. Everything between the braces is a property/value pair, ending in a semicolon.

.my-box {
  background: #1a1f29;
  padding: 20px;
}
Common mistake: forgetting the semicolon between properties, or the dot before a class name — my-box without the dot targets an element literally named my-box, which doesn't exist.

4Flexbox — real layout

Turning an element into a flex container changes how its children are arranged — in a row by default, instead of stacked.

.row {
  display: flex;
  justify-content: space-between;
  align-items: center;
}
PropertyWhat it does
display: flexturns on flex layout for this element's children
justify-contentspacing along the row — space-between pushes items to both edges
align-items: centervertically centres items within the row
gapspace between items, without needing margin on each one
Common mistake: setting display: flex on the wrong element — it needs to go on the parent (the container), not the items inside it.

Check yourself

1. What does forgetting the dot in my-box { ... } actually target?

Without the dot, the browser reads it as a tag name selector, not a class — since no element is actually called "my-box", the rule silently matches nothing.

2. Where does display: flex need to go to lay out two items side by side?

Flex is a layout mode for a container's direct children — it has to sit on the parent, not the items you're trying to arrange.

3. Which font-weight reads as genuinely bold?

400 is normal weight. 700 (or the keyword bold) is what actually renders as bold text.
